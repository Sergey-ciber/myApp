# Правила работы с репозиторием

## Запрет автоматического push в GitHub

- **Никогда не выполняй `git push` автоматически.** Любой push — только после явного разрешения пользователя в текущем сообщении.
- Запрет распространяется на все ветки, теги и force-push, а также на публикацию релизов и отправку коммитов из локального репозитория в удалённый.
- Коммиты создавать можно, но после коммита нужно остановиться и сообщить пользователю, что изменения готовы к отправке, и дождаться отдельного указания.
- Если пользователь просит «задеплоить» или «выложить», сначала уточни, разрешён ли push, и не выполняй его без подтверждения.
- Не обходи запрет через сторонние способы доставки кода (bundle, скрипты деплоя, CI-триггеры, API GitHub) без прямого разрешения пользователя.
- **НЕ ПУШЬ ИЗМЕНЕНИЯ В GITHUB БЕЗ ЯВНОГО РАЗРЕШЕНИЯ.** Даже если задача выполнена и коммит создан — не выполняй `git push`. Всегда жди прямого указания пользователя «запушь», «отправь», «push» или явного разрешения.

## Особенность окружения

- Локальный `git push origin main` завершается ошибкой `Invalid username or token`; на сервере `/opt/taskmanager` настроен deploy key с правом записи.
- Это не является основанием для автоматического push — порядок остаётся прежним: явное разрешение пользователя, затем отправка.
